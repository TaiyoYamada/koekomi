# 0003. 作品の音声はクライアントが所有する

## 状況

生成音声を、サーバーの**絶対URL**で参照していた。

```ts
voiceUrl: 'https://xxx.trycloudflare.com/files/voice-ab12-3.wav'
```

この文字列は localStorage に永続化される。したがって:

- トンネルが再起動してURLが変わる → **保存された作品が壊れる**
- 別の台にフェイルオーバーする → **すべての音声リンクが死ぬ**

しかも再生側は `onerror` を握りつぶしていたので、
**エラーも出ずに無音の紙芝居**になっていた。

さらに、劇場は再生前に全音声を fetch して blob URL にしていた。
つまり**バイト列はすでにクライアントに来ている**のに、
揮発する Map に置いていただけだった。

## 決定

- ドメインは `AudioRef`（IndexedDB のキー）だけを持つ。**絶対URLを持たない。**
- 生成が完了した行は、**その瞬間に手元へダウンロード**する。
- サーバーは TTL 付きの一時ファイルしか持たない、ステートレスな計算機とする。

## 理由

3台を冗長構成で持つなら、成果物がサーバー局所だと**フェイルオーバーが
作品を壊す**。「サーバーはいつ落ちても・入れ替わってもよい」という
不変条件が無いと、台数は冗長化として機能しない。

`artifactId` は「サーバー側レンダリングに使えるかもしれない」ヒントとしてだけ
持つ。無効になっても作品は壊れず、クライアント書き出しに落ちるだけ。

## 結果

- フェイルオーバーで失われるのは**未完了の行だけ**になった
- リロードしても完全に復元できる
- E2E で `保存データに "http" が1文字も含まれないこと` を検査している
- 引き換えに、端末のストレージを使う（数MB。IndexedDB の割り当てには十分収まる）
