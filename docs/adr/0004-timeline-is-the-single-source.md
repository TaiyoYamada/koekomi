# 0004. 再生規則はタイムライン1つに集約する

## 状況

「いつ・どの写真を・どの字幕とともに・どの音声で映すか」という規則が、
2箇所に**独立して実装**されていた。

- `Theater.tsx` の再生ループ（250ms待ち → 各行 → 150ms → コマ間）
- `export-video.ts` の `buildTimeline`（同じ定数を再定義）

片方を直すともう片方とズレる。しかもサーバー側レンダリングを足すと
**3つ目の実装**が生まれるところだった。

## 決定

`domain/timeline.ts` に **タイムラインというデータ構造**を1つ置き、
次の3者がそれを解釈する。

1. 劇場プレイヤー（再生）
2. クライアント書き出し（MediaRecorder・フォールバック）
3. サーバーの ffmpeg レンダリング（本番）

サーバーへは**組み上がったタイムラインをそのまま送る**（`POST /render`）。
サーバー側は組み立てを持たない。

## 理由

プレビューと書き出した動画が一致することを、**構造で保証**したい。
「たぶん一致しているはず」ではなく、「同じ入力を解釈しているから一致する」に変える。

## 結果

- 定数（コマ間・セリフ間・無音時の長さ）が1箇所になった
- 不変条件をプロパティテストで守れるようになった
  （区間が連続する / 合計が一致する / 任意の時刻で必ず区間が返る）
- サーバーは受け取ったものを描くだけになり、検証（SSRF対策含む）に集中できる
