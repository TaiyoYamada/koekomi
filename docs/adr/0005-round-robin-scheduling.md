# 0005. 生成はラウンドロビンで配る

## 状況

作業単位を1行にした（[0002](0002-one-line-is-the-unit-of-work.md)）あと、
`scripts/load-test.py` で **10人同時 × 8セリフ、1行1.5秒、ワーカー1本**
を実測したところ、ジョブ単位の FIFO では次のようになった。

```
最初の1行が届くまで   p50 56.5秒   ← 子どもが1分近く「何も起きない」
完了                  #0 は 13秒 / #9 は 123秒（差が10倍）
```

10人目は前の9人ぶん72行が終わるまで、**1行も返ってこない**。

## 決定

キューを**ラウンドロビン**にする。ワーカーは子どもごとに1行ずつ交代で取り出す。

## 理由

全体の所要時間（最悪ケース）は変わらない。変わるのは**体感**だけ。
しかし子どもにとっては、その体感がすべてに近い。

- 1分間なにも起きない → 「こわれた」と思って別の操作を始める
- 進捗バーが動いている → 待てる

教室では「全員が同じくらいで終わる」ほうが運営しやすい、という事情もある。

## 結果

同じ条件で再測定した実測値:

```
                    FIFO      →  ラウンドロビン
最初の1行まで       56.5秒    →  10.7秒   （5.3倍）
全員が終わるまで    123.0秒   →  123.3秒  （変わらない）
```

**最悪ケースを悪化させずに、体感待ち時間だけを 1/5 にできた。**

引き換えに:

- 平均完了時間は伸びる（67.6秒 → 116.2秒）。
  「一部の子だけ早く終わる」より「全員が揃って終わる」を選んだ。
- `queuePosition` の意味が変わった。「前で待っている人数」ではなく
  **「いま一緒に使っている人数」**になり、UIの文言も変えた。
